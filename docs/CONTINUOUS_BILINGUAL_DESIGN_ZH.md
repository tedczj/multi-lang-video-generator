# 连续画面的双语试制设计（2026-09-17）

## 目标与证据

输入为用户提供的 YouTube `73XAgADpBqY` 及桌面录屏 `录制于 2026-09-17 01.11.30.mp4`。
原片已按 `bv*+ba/b --format-sort-force -S res,fps` 下载，最高可用 1920×1080/30 fps，约 347 秒；录屏为 2560×1600、108.948 秒 VFR。录屏内有效画面为 x=0,y=80,w=2560,h=1440；这个裁剪只用于取证，不应用于输出成片。

初步对应帧：录屏 20/30/40/50 秒分别接近原片 20.5/25.9/31.2/36.6 秒。说明正文画面主要连续慢放到约 0.54 倍速（时长约 1.85 倍），而非逐句额外停帧。自动 ASR 显示中文先于英文；ASR 有幻觉及边界误差，不作为逐字正确或真人试听通过的依据。静态背景可能对应原片多个时刻，须保存歧义，不能把最近邻回跳当成重播。最终量化结果与输入哈希见 `verification/jttw-20260917/`。

可确认的是输出行为，不能从录屏证明作者使用的软件、算法或参数；字幕确有重排，但本轮不重绘英文。

## 实施范围与决策

先完成可独立执行的试制 CLI、真实片段 A/B 成片、失败用例测试及证据。现有 N16 gap-first、N17、N18 和 Studio 默认策略不切换；新的试制时间线是独立格式，禁止交给旧渲染器误解释。完整自动句组/OCR/TTS/Studio 接入列为后续集成，不把试制标成全片上线。

1. 取证：中央画面特征匹配，排除水印、字幕和播放器；用稳健直线拟合量化速度、残差、匹配覆盖率。保留原始逐点数据和匹配歧义。
2. 试制：使用已下载原片、真实英文 ASR、逐句中文音频、人工核对的字幕页坐标，生成相同音轨的停帧和连续慢放两版。
3. 验证：输入哈希、完整帧序列、严格递增 PTS、完整 PCM、双语音轨间隔、字幕布局、显示尺寸、实际输出解码，以及真人试听/观感状态分别记录。

## 时间线与声音算法

以相邻的安全整帧边界划分句组，覆盖输入片段的所有原始帧和全部原始 PCM，不拆英文发声。多个紧邻台词可先合组再配中文。每组输入 `start_frame/end_frame`、中文 PCM、译文及当前英文页面的源帧区间/边界框。CLI 只接受无间隙、无重叠的分组和 48 kHz 双声道 s16 PCM。源文件首帧非零或音视频结束不一致等不能确认的情况应明确拒绝，先用已有 N04 规范化契约准备。

本次选中文先行：

- 每组输出音频为「中文原速 + 1 秒静音 + 完整该组原声原速 + 1 秒静音」。同一组中文只出现一次；两版使用同一条生成的 PCM。
- 组长 `D_out = D_zh + 1s + D_source + 1s`；画面速度 `v = D_source / D_out`。不截断或加速声音，不把英文拖到画面慢速播放。
- 连续版：每个原始帧恰好输出一次，`t_out = group_output_start + (t_source-group_source_start) × D_out / D_source`，按原始 PTS 比例映射。原始静止画面仍静止，但不为中文新增连续 hold。
- 对照版：组内原画面正常播放，剩余时间重复组末带英文字幕的帧；中文先行的音轨完全相同，仅用于隔离画面策略差异，并不声称是旧 N16 的完整复刻。
- 不用光流插帧、不循环动作、不倒放、不剪掉画面。所有慢放只发生在输出时间线，下载与 N04 原素材保持原样。
- 无法兼得：插入中文、保留全量英文、声音不变速、视频不变速且不重播/停帧。选择连续慢放意味着动作变慢及原英文与嘴型/音效画面关系变化。这是显式取舍。
- 本试制不分离人声/伴奏；原背景音乐/音效随原声保留，中文区间没有复制原英文背景。无缝背景音需要单独取得 M&E 或经过验证的分离轨，不能通过简单复制带英文的混音解决。

## 字幕

保留源片英文；中文字幕紧贴当前英文框，上下规则仍按 spec.md。每页绑定源帧范围，经各版的帧映射显示，覆盖静音空档。录屏重绘英文的外观不在本轮实现范围。字幕出现与当前画面页一致，可能和被重新排布的声音不完全同时，列入真人审查。无可靠页面框则拒绝带字幕成片，不能自动假定统一底部坐标。

## 可验证完成标准

- 单元测试：精确时长、0/负参数、超慢速度、页区间越界/不覆盖、无当前英文框、组不连续、音频格式及长度不符，失败时不产生可交付 PASS。
- 媒体测试：用独立解码比较无字幕连续版的每个源帧内容与顺序；验证输出帧数等于源帧数，PTS 递增且跨度正确；直接比较 PCM 各段内容，证实原声和中文未变速/截断；拒绝输出原路径覆盖。
- 真实验证：同源、同中文、同英文、同完整输出 PCM 的两版；同样 1920×1080，无新底栏；逐页检查边界与静音时字幕保留。输出为紧凑 H.264 + PCM 的 MKV 试制文件，另生成便于播放的 MP4；有损编码的像素偏差与 AAC 偏差不得误标成源像素/PCM 一致。
- 速度过慢（低于 0.4×）应拒绝并提示重组/人工调整，不用停帧偷偷兜底；0.4× 为试制工程阈值，不代表观感已通过。
- 状态分别为 implementation / automated_checks / visual_spot_check / human_listening / formal_acceptance。技术通过不能自动转人工通过。

## 本轮执行结果与边界

取证最终拟合：源秒/录屏秒 = **0.534667**，即画面时间约拉长 **1.8703 倍**；区间 18.0–108.6 秒，272 个可靠候选点中 239 点落入主映射，95% 残差约 0.249 秒。录屏以 5 fps、原片以 10 fps 取证采样，这不是导出的帧率。源片实际时钟为 **30000/1001 fps**（网站整数标注 30）。静态/水印遮挡点不参与主拟合。这个数值是相对录屏观察到的速度，不能反推出作者软件中的精确倍率，亦不证明所有时刻都没有局部停顿。

三句样片使用源帧 `[720,1200)`，共 480 帧、16.016 秒；无损截取的逐帧 YUV MD5 全部匹配原片。音频从完整解码 PCM 的 `[1153152,1921920)` 取出。A/B v2 输出 34.301375 秒，句组速度约 0.468/0.446/0.502×。之所以不直接统一设成 0.535×，是本试制保留每句的完整中英文与 1 秒间隔，按实际中文时长计算，而不是把参考片的倍率当作硬编码。

实现入口：`mlvideo.reference_motion`、`mlvideo.continuous`、`mlvideo.continuous_verify`。单元测试 106 项通过；独立的小型真实 H.264/PCM/AAC 集成测试通过，涵盖解码、时间戳、逐段音轨相等及文件篡改拒绝。真实样片技术结果见 `verification/jttw-20260917/media-checks-v2.json`，复现命令见同目录 `README.md`。

已完成：实测分析、设计、独立试制 CLI、真实素材 A/B、自动检查、部分视觉抽查。未完成：全片自动句组/OCR 集成、Studio 默认策略切换、CosyVoice 音色试听、嘴型/背景音自然度人工验收。英文在参考录屏里是否变速或重新配音也没有被本次声音取证确认，不能把“原声 1×”反推给参考作者。
