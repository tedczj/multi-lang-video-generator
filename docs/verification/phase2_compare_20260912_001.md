# 第二期选型实测：PaddleOCR 两接口与音色克隆

日期：2026-09-12。范围：独立部署、比较测试与复核材料；未实现第二期业务 worker，未作最终选型。

## 环境与复现边界

- Apple M4 Max，64 GiB 内存。复用 `cartoon-tts-root` 已有模型与 Python 依赖；额外依赖使用独立环境，原服务代码未改动。
- 原始 PaddleX API：`http://127.0.0.1:58081/ocr` 与 `http://127.0.0.1:58080/layout-parsing`。PaddleOCR 3.6.0、PaddleX 3.6.1、Paddle 3.2.2；检测在 CPU，VL 使用既有 MLX-VLM 0.5.0 / PaddleOCR-VL-1.6。
- 这是 Mac 部署组合测试，并非 NVIDIA Compose 性能测试。Compose 没有完整镜像标签和 VLM 配置；两个 API 当前均声明 GPU 0，不能按注释当作双 GPU 隔离。
- Qwen：`Qwen/Qwen3-TTS-12Hz-1.7B-Base`，revision `fd4b254389122332181a7c3db7f27e918eec64e3`；PyTorch 2.10.0、Transformers 4.57.3。
- CosyVoice：`FunAudioLLM/Fun-CosyVoice3-0.5B-2512`，revision `29e01c4e8d000f4bcd70751be16fa94bf3d85a18`；官方源码 `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`，独立 PyTorch 2.3.1 / Transformers 4.51.3 环境。
- TTS 均为 CPU、float32、8 个 PyTorch 线程，逐句调用，完整保存返回音频；Qwen 使用 eager attention，CosyVoice 使用其默认 SDPA 路径。模型来自挂载盘，加载耗时与生成耗时分开。环境安装/导入可能产生后台负载，因此耗时仅作本轮部署测量，不能解释为纯模型架构差异。
- 本机初查只有约 1.4 GiB 可用空间；新增模型和 CosyVoice 环境放在 `/Volumes/备份/mlvideo-phase2-model-tests-20260912/`。模型与测试产物未进入 Git。

配置、实际 OpenAPI、运行环境、下载 revision/etag、样本哈希和原始请求响应保存在 [本地证据目录](../../evidence/phase2_compare_20260912_001/)。该目录被 Git 忽略，需要随本机证据一并保留，不能假定仅拉取仓库就能取得音频。

## OCR 结果

### 真实文档：5 页旧刊，125 个参考文本单元

输入为本机 `Image-014.pdf`，参考为已有 `Image-014-4S.json`；参考来源的人工审核身份本轮未独立验证。沿用现有评测器的 Levenshtein CER，去除空白及 Markdown/HTML，保留繁简体差异；阅读顺序计入误差。

| 原始接口 | 第 1 / 2 / 3 次完整请求耗时 | 三轮 CER | 说明 |
|---|---|---|---|
| `/ocr` | 50.81 / 50.42 / 50.32 秒 | 均为 88.13% | 存在阅读顺序和繁简体差异 |
| `/layout-parsing` | 20.27 / 20.07 / 20.08 秒 | 均为 32.31% | 对该复杂文档明显更好，但仍有大量错误 |

两路均 3/3 返回 HTTP 200 且业务 `errorCode=0`。这里的“第 1 次”不是冷启动：服务之前已处理字幕样本。逐页指标和原文见 [文档指标](../../evidence/phase2_compare_20260912_001/native_document_metrics.json)。

另行复测旧项目封装 `/ocr/pdf` 与 `/ocr/pdf/vl`，耗时 27.4 / 20.6 秒，CER 91.11% / 33.41%。它们带有各自参数与后处理，只作复用环境的先导测试，不能与原始接口混算。见 [封装接口报告](../../evidence/phase2_compare_20260912_001/ocr_document/comparison.md)。

### 字幕控制样本：3 帧，每接口每帧重复 3 次

来源为项目已有 `sources/result.mp4`：无字幕帧、第一句双语字幕、第二句双语字幕。它是合成演示视频，不是覆盖真实复杂背景的视频集。目标文字经过本轮画面目视核对；没有独立逐行框真值，本轮不声称已完成 IoU 验收。

默认配置会失败：常规 OCR 的文档矫正影响字幕识别和坐标；VL 将画面判为图表，默认不识别图表中的文字。18 次 HTTP 请求均成功，但不代表内容成功。原始失败结果保留在 `ocr_native_001/`。

第二组测试明确改变参数：两路均关闭文档方向识别和矫正；常规 OCR 关闭文字方向识别；VL 关闭版面检测、设置 `promptLabel=ocr`，每次最多 512 token。

| 视频参数组 | 两张有字幕帧的文字 | 几何输出 | 除首次请求外的单帧耗时中位数 |
|---|---|---|---|
| `/ocr` | 正确读出两组中英字幕 | 返回独立字幕行框 | 0.932 秒 |
| `/layout-parsing` | 正确读出两组中英字幕 | 只有整帧框，未提供独立字幕行位置 | 0.827 秒 |

均保留了画面左上时间码；没有字幕的控制帧也会识别时间码，不能把“有文字”直接当作“有字幕”。[查看识别文字和框](../../evidence/phase2_compare_20260912_001/ocr_review.html)。

暂定建议：视频硬字幕定位优先考虑 `/ocr` 的视频参数组；复杂文档识别优先考虑 VL。尚不能把三帧控制测试推广为真实字幕质量结论，20 帧真实烧字样本、框 IoU 和时间边界测试仍属后续必需验证。是否需要保留第二路回退应由失败样本决定，本轮不实现回退逻辑。

## 音色克隆

两位英语参考说话者分别来自 Qwen 官方克隆示例及 LibriSpeech 参考片段；固定参考文件、转录、中文目标句和随机种子。每位六句、三轮，覆盖数字、否定、专名、感叹、长句和尾句；额外首次请求单列。无参考向量预缓存，每次均从参考音执行克隆。

Qwen 使用 Base 的 `generate_voice_clone`；CosyVoice 使用官方 `inference_zero_shot`，按官方前缀携带英语转录，`stream=False`，完整拼接返回块。中文测试句中的数字已写成汉字；CosyVoice `text_frontend=False`。两路都使用各自采样实现，种子 42/43/44 不代表随机过程相同。

两路各完成 36/36 条正式译音，另各保存两条首次请求音频。全部原始 WAV 的哈希、采样率、采样数与实际解码结果一致；没有非有限采样或幅值削波。以下为 36 条正式译音的统计，不含首次请求，也不包含先导 Qwen 冒烟结果。

| 模型及调用方式 | 单句完整生成耗时中位数（范围） | RTF 中位数（范围） |
|---|---|---|
| Qwen3-TTS Base / voice clone | 9.34 秒（6.00–13.94） | 2.151（2.012–2.400） |
| CosyVoice3 / zero-shot | 8.16 秒（5.99–10.64） | 1.709（1.397–2.720） |

RTF 是完整请求耗时除以输出音频时长，包含每次参考音处理；不同模型输出语速/时长不同，因此同时列出单句耗时。不能将这里的差异直接解释为模型固有速度差异或 NVIDIA 部署性能。[完整统计](../../evidence/phase2_compare_20260912_001/tts_summary.json)。

[打开 A/B 试听页](../../evidence/phase2_compare_20260912_001/review.html)，或通过运行中的本机页面 [http://127.0.0.1:8766/review.html](http://127.0.0.1:8766/review.html) 试听。页面固定展示每个句子的第 1 轮，共 12 对，并附两段参考音；A/B 对应可折叠查看，未挑选最好样本。试听副本统一做 RMS 增益处理并保存为 PCM16，原始 FLOAT WAV 和三轮结果保留。

首轮辅助检查采用相同的 Whisper base，对首轮 24 条正式音频转录。它把繁体字、阿拉伯数字、英文拼写的专名与中文目标混合输出，因此原始字符串 CER 不能当作真实发音错误率。两模型的专名句均出现英文转录，CosyVoice 第二位参考说话者第 6 句还有连续重复的异常转录。

随后使用同一 Whisper small 复核 24 条基线音频及 4 条针对性补测音频，全部完成。small 将上述短尾句识别为“谢谢您的帮助，我们明天再见”，未复现 base 的长串重复，故不能将 base 的结果判定为 TTS 重复故障。专名仍有英文拼写和音译差异，需结合试听确认。两级识别器的结果均保留在 `audio_assessment_001/` 和 `audio_assessment_small_003/`，不隐藏不利结果，也不把 ASR 表现直接等同于 TTS 内容质量。

CosyVoice 额外按官方用法调用 `inference_cross_lingual`，对两位参考说话者分别补测专名句和短尾句，种子为 42；另各保存首次请求。4/4 个目标请求均成功。small 对该模式的专名转录更接近目标中文，但仍有“麦克尔/迈克尔”等拼写差异。这只是针对性测试，不能宣称该路径已通过完整六句三轮矩阵。

[查看 Qwen / Cosy zero-shot / Cosy cross-lingual 三路针对性试听](../../evidence/phase2_compare_20260912_001/cross_review.html)，或打开 [本机复测页](http://127.0.0.1:8766/cross_review.html)。若最终选择 cross-lingual，应先补齐该路径的完整矩阵再锁定参数。

CosyVoice 自带 CampPlus 编码器测得的首轮参考音相似度中位数：Qwen 0.576、CosyVoice 0.713。该编码器属于 CosyVoice 体系，不是独立评测器；这些数字只作辅助，不能据此宣布音色胜负或自然度通过。

部署过程中的缺依赖失败、CosyVoice 的参考转录长度警告和 attention 警告均保留在日志中；环境部署错误与实际生成结果分别记录。当前人工试听和最终选型仍为待完成，不能以自动解码成功代替听感验收。

## 用户试听反馈与前导声音诊断

用户反馈：CosyVoice zero-shot 比 cross-lingual 和 Qwen Base 更仿真；但复测页参考说话者 2 的“谢谢你的帮助，我们明天再见。”开头有明显细小声音。因此音色方向优先考虑 zero-shot，该样本不能因解码/ASR 成功而视为听感通过。

对应原始文件是 `cosy_libri_003/r0_s6.wav`，试听文件为 `listen_cross/cosy_libri_003_s6.wav`。本次逐采样比较确认：采样率均为 24 kHz，采样数均为 153600；试听文件等于原始波形乘以 1.490384（约 +3.466 dB）再量化到 PCM16，最大残差不超过一个 PCM16 量化步长。前导小幅信号在原始生成中已存在，试听增益进一步放大了它，不能归因于播放页新增声音。

| 同一参考音及目标文本 | 全长 | 连续显著能量首次出现 |
|---|---|---|
| [第 1 轮，种子 42](../../evidence/phase2_compare_20260912_001/cosy_libri_003/r0_s6.wav) | 6.40 秒 | 约 2.60 秒 |
| [第 2 轮，种子 43](../../evidence/phase2_compare_20260912_001/cosy_libri_003/r1_s6.wav) | 4.16 秒 | 约 0.62 秒 |
| [第 3 轮，种子 44](../../evidence/phase2_compare_20260912_001/cosy_libri_003/r2_s6.wav) | 2.96 秒 | 约 0.34 秒 |

测量定义：20 ms 窗 RMS，连续三窗高于 −40 dBFS；这是诊断能量起点，不是人工核准的首字位置，也不能直接当作裁剪边界。第一轮前导段含间歇性低幅信号，0–2 秒各 100 ms 窗 RMS 约在 −66 至 −44 dBFS。结果说明前导段随采样轮次明显变化；尚未证明它具体来自参考音背景、呼吸拟合或模型生成的其他伪影。

本次仅诊断并记录反馈，原始及试听音频未改动。前导异常需纳入后续质量验证，不能仅凭幅度阈值裁掉开头，以免误切轻声或首字。

## 本轮交接与边界

完成：两种原始 OCR API 部署、42 次原始接口请求（36 次控制帧、6 次真实文档）、旧项目封装先导测试、两种真实克隆模型部署、72 条正式基线译音、4 条 cross-lingual 针对性译音、两级 ASR 复核、原始与试听音频完整性检查。

用户音色偏好已明确倾向 CosyVoice zero-shot；其前导细小声音问题尚未解决，OCR 接口/参数尚待选定。待后续验证：真实烧字视频样本覆盖、字幕框与时间边界、前导声音与首字保护、人工自然度/尾音复核，以及最终选择路径的完整矩阵。第二期翻译、克隆 worker、数据库接入和成片业务代码均未开始。

两组试听页及其 38 个 PCM16 音频文件已做本地 HTTP/文件解码检查；浏览器连接不可用，本轮未取得浏览器截图，不宣称已完成浏览器视觉验收。
