# 系列角色配音工作台：实现与验证报告

## 交付性质

这是用户上传源码 ZIP 上的增量代码实现，包含真实管理页、API、MySQL 迁移、持久任务执行器、现有 CosyVoice3/FFmpeg 链路接入与测试；不是只有设计文档的包。以本地上传快照为基线，没有把 GitHub main 当作已核对一致的源快照，也没有推送 GitHub、创建分支或 PR。

生产仍使用原项目 MySQL 8.4。`tests/studio/sqlite_protocol.py` 只是本次自动化测试使用的 SQL 协议适配器，不是生产数据库替代实现。

## 已实现功能

| 业务 | 实现 |
|---|---|
| 系列资源页 | 创建系列、角色和视频条目，显示输入、分段审核进度、任务与候选成片 |
| 现有素材接入 | 按已有 source/analysis artifact ID 绑定，不凭文件名猜测；拒绝音频/时钟/字幕证据错配 |
| 人工审核 | 原声/上下文播放，英文和中文编辑，角色确认，原子批量标角色，乐观锁冲突提示 |
| 分段修订 | 修改边界、拆分、合并和补录漏句；创建新版本，仅完全未变化的片段携带有来源的标注 |
| 角色素材 | 全部已确认原声与优选参考分开；1–30 秒连续原声提取，准确参考原文保存，独立批准及停用 |
| 固定声音 | 一个声音版本固定参考、CosyVoice3 部署信息、seed；先生成测试音，再明确人工批准并发布 |
| 整集计划 | 冻结角色、标注、分段、译文、声音、模型和参考；计划材料化后逐句使用明确固定产物 |
| 配音及重试 | 原 CosyVoice3 N11 与 N12 QA 接入；新执行独立版本，失败保留证据，不自动反复调用模型 |
| 结果选用 | 试听后选用某个精确句子结果；新生成不自动改选用，合成入队时冻结全部选用 |
| 候选成片 | 复用 N16/N17/N18/N19，按实际译音时长重新规划，保留原视频与原音逻辑及历史产物 |
| 受控跨集引用 | 仅新增 N10/studio_import_reference 的指定端口放行；检验同系列、已批准参考、固定声音和内容摘要 |
| 暂停与审计 | 等待人工只保存持久状态；单独队列进程、独立目录短事务、追加事件、失败后手工重试 |
| 安全边界 | 仅本机绑定、Host/Origin/CSRF 检查、严格请求字段、已登记媒体访问、真实 WAV 范围播放 |

自动跨集声纹分类不在已实现清单中。当前“局部分组建议”只用同一集/同一分段版本中已确认的局部声学簇提供提示；没有自动确认、高准确率承诺或隐式角色合并。字幕翻译建议同样不会覆盖已确认译文。

## 自动化证据与边界

**最终 pytest：105 passed，0 failed，0 errors，0 skipped。** 结果见 `studio-tests.xml` 和 `studio-tests.log`，汇总写入 `release-checks.json`。测试由以下四层构成：

- 原项目 73 项单元及无模型媒体回归。
- 新目录状态机 19 项，API/安全/PCM 范围播放 6 项。
- 跨集配音链路 3 项：真实 Engine、真实非模型 worker、真实 FFmpeg、原字幕/时间线合成；N11 是明确标记的提示音测试替身，ASR 输入是声明的测试夹具。
- 备份与额外门禁 4 项，包括 FAIL 持久化及阻止下游消费。

“测试替身”只用于 `tests/`，生产 API 不提供开启替身的选项。测试生成的 WAV 是明显提示音，不是真实英文或中文语音。它们验证实际调用次数、文件、采样数、版本、关联、重试和合成结构，不能证明音色克隆像原角色。

另外，`browser-smoke.json` 记录 6 个 Chromium DOM 工作流检查：建角色、标注与译文保存、WAV 解码/时长、筛选、分段修订、角色参考/声音页面。浏览器环境的管理策略禁止所有网络导航，因此使用真实前端 HTML/CSS/JS + FastAPI TestClient 传输桥完成这些检查；**不能称为浏览器通过原生 HTTP 访问部署的端到端验收**。源代码另外保留 `browser_smoke_http.py`，供未受该策略限制的本地环境执行。

`live-http-smoke.json` 另行记录真实 Uvicorn 监听本机端口后，通过 httpx 执行的 5 个 HTTP 检查：页面读取、CSRF 拒绝、带 token 的目录写入、WAV Range、跨源拒绝。数据库仍是测试适配器。

三张 `studio-*.png` 是真实前端渲染的界面截图，页面明确标为“界面测试”；里面的角色、记录与音频均为测试数据，不是已经处理了用户的实际 Little Fox 视频。

## 修复的原有问题

原 `Engine.commit` 会从产物计算质量状态，但没有将该值更新进 executions。此次补上 `quality_status` 持久化；测试用静音输入得到 FAIL 后，确认 Engine 拒绝该产物作为下游输入，声音发布门禁也拒绝该结果。历史数据库的旧行不会被静默批量改写，需要时按明确流程重做 QA。

## 包含与排除

交付包含当前源码、增量迁移、管理页、设计、使用说明、测试、日志与截图。不包含模型权重、字体、实际用户视频、私有配置、密钥、运行数据、虚拟环境或 `.git` 历史。原 ZIP 中 `sources/` 的三份旧研究/原型嵌套 ZIP 不影响本项目运行，本交付不再次打包；原始上传文件保持不变。

补丁按上传 ZIP 的原始源码生成，不假定远程分支与上传文件完全一致。先执行 `git apply --check`；保留本机 `.env`、`config/local*.json` 和 data_root。详细步骤见 `docs/STUDIO_QUICKSTART_ZH.md`。
